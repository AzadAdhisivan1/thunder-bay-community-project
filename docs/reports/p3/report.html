4. Updated design artifacts

Figure 1: Architecture after Sprint 2. Layers are unchanged from P2; dashed boxes are the Sprint 2 additions.
  • PostGIS location column. Migration 0002 adds services.location, a geography(Point, 4326) column generated by the database from latitude and longitude, with a GiST index. The seed script and CSV stay unchanged and the column can never drift from the coordinates.
  • Distance in the API. /api/services, /api/search and /api/services/{id} accept optional lat and lng. Each result gets distance_km and lists are sorted nearest first; an optional max_km limits the radius. Without a location the API behaves exactly as in P2, so the site still works when location is denied.
  • Same layering. Distance is computed in the CRUD layer (PostGIS on PostgreSQL, the same formula in Python for the SQLite unit tests). Ranking (US-08) and the plain-language parser (US-07) will sit between routers and CRUD and reuse the keyword search as their fallback.
  • Contract first. docs/api.md documents the new parameters so the frontend and backend can again be built in parallel.

5. Iteration review

Planned: US-06 (location and distance), US-07 (plain-language search) and US-08 (ranked results), 21 points, taking the project from 25% to 53% of the backlog.

Completed so far: the US-06 backend is merged. Migration 0002 adds the generated PostGIS location column. All three service endpoints accept a location and return distance_km nearest first, with an optional radius, and the frontend API client accepts the location. On the 50 real listings, distances from City Hall range from 0.13 to 10.59 km, 12 services lie within 2 km, and the request takes about 17 ms. Testing grew from 92 to 144 tests: 40 distance tests, 4 API-client tests, and 8 PostGIS tests that run against a real database in CI, closing the gap P2 noted that SQLite could not test PostGIS. While adding the migration we found and fixed a latent risk: Alembic's autogenerate would have dropped the PostGIS image's own tables. Sprint 2 tasks for the other stories are assigned in the README with owners, files and acceptance criteria.
